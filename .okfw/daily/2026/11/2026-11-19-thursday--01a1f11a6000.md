# 2026-11-19 Thursday

## Changed
- Opened Phase 9 and ISSUE-011. `third_party/tree-sitter-zig/grammar.js` is now the Zig grammar of ztree (Task 9.1, ADR-0012).
- The grammar adds four changes to the patch of ADR-0010: empty containers, an error set as a container field, a slice of an `if` type and an identifier as the asm clobbers.
- Added `TestZigEmptyContainersAndRareForms`. Closed ISSUE-011.
- Phase 10 (ISSUE-012, ADR-0013): merged the branch `ztree-runtime` into `main` as a fast-forward. semscope now parses with the ztree Go binding.
- Added the task `ztree` to the `ZMakefile` and the `Makefile`. It builds `libztree.a` before `build`, `test`, `lint`, `selfscan` and `parity`.
- Filed ISSUE-013: `third_party/tree-sitter-zig` has no user in the build now.
- Phase 11 (ISSUE-013, ADR-0014): removed `third_party/tree-sitter-zig`, its `replace` directive, `TestZigParserHash` and the `third_party` exclude of `.semscope.cue`. ADR-0014 deprecates ADR-0010 and ADR-0012.
- Phase 12 (ISSUE-014): `scripts/parity_corpora.py` listed go-tree-sitter, so `go list -m` failed and the Go parity corpus held the fixture only. The script now runs one `go list -m` for each module. It gives six Go corpora again.
- Reviewed semscope against ztree `70fe5e7` (Phase 18). `zig build lib --release` gives the same `libztree.a` (SHA-256 `2cc1ddd1…`) as `libhash.go`. The binding tests pass.

## Learned
- `tree-sitter-cli` 0.25.10 gives the same `parser.c` in semscope and in ztree from the same `grammar.js`. A copy of `grammar.js` is enough to keep the two grammars the same.
- The parity test does not change: the adapter reads no node that the four changes touch.
- After the merge, `zmake parity` passes on the Zig corpora (the fixture, zmake, the Zig 0.17.1 standard library) and on the Go fixture.
- With the full corpus list, `zmake parity` passes on nine corpora. The ztree runtime causes no new Go divergence.
- zmake `src/`: semscope (`-r nasa-p10 -r .semscope.cue`) and `scripts/nasa-lint.py` both give 0 findings, 306 functions and 614 assertions.
- lexis: `cmd/nasa-lint` of lexis, `scripts/nasa-lint-go.py` of semscope and semscope give 0 findings, 174 functions and 352 assertions. The semscope scan needs an overlay that matches ADR-0003 of lexis: R3 and R6 off, and `scripts/` excluded. Without the overlay, semscope gives 77 R3 findings, 11 R6 findings and one R5 finding for the Python scripts. lexis has no `.semscope.cue`. `go_types: true` for R7 gives 0 findings in lexis too.
