---
title: Suppressions & Excludes
description: Allow one finding with a source comment, or skip a path with an exclude pattern.
---

semscope gives two ways to accept code that breaks a rule:

- A suppression tag allows one rule on one line.
- An exclude pattern skips a file or a directory for all the rules.

## Suppression tags

Write the tag `semscope: allow(RULE-ID)` in a comment on the line of the finding or on the line above. Give the reason after the tag.

```go
// semscope: allow(NASA-P10-06) the program compiles the pattern once and never writes it
var identRE = regexp.MustCompile(`^[A-Za-z_][A-Za-z0-9_]*$`)

f.Close() // semscope: allow(NASA-P10-07) the read is complete; a close error changes nothing
```

```python
DEFAULTS = {}  # semscope: allow(NASA-P10-06) a read-only table that the module fills once
```

- The tag applies to one rule ID. To allow two rules on one line, write two tags.
- semscope finds the tag as text on the line, so the comment syntax of each language works.
- A finding without a location has no line. A tag cannot allow it. Omit the rule or tune its parameter.

### nasa-lint tags

semscope also reads the tags of the oracle scripts `nasa-lint.py` and `nasa-lint-go.py`. The tag `nasa-lint: allow(R<n>)` allows the rule `NASA-P10-<n>`:

```zig
const buf = try allocator.alloc(u8, n); // nasa-lint: allow(R3) the init path sizes the buffer once
```

So a code base that the oracles check needs no new tags.

## Exclude patterns

An exclude pattern skips each path that it matches. It also skips each path under a directory that it matches.
A pattern uses the [`path.Match`](https://pkg.go.dev/path#Match) syntax on paths relative to the scan root.

| Pattern | Skips |
|---|---|
| `gen` | The directory `gen` and all the files under it |
| `gen/*.go` | The Go files in `gen`, not in its subdirectories |
| `*_generated.go` | Each matching file at the scan root |
| `internal/*/mock_*.go` | Mock files one level under `internal` |

The `*` wildcard does not match a `/`.

### In a ruleset

The `exclude` map of a ruleset maps a pattern to a reason. Each entry needs a reason.

```cue
package overlay

exclude: third_party: "vendored grammar with a generated parser"
exclude: "gen/*.go":  "generated by the protobuf compiler"
```

The exclude maps of all the sources compose, the same as the rules.

### On the command line

The flag `--exclude` adds a pattern with the reason `--exclude flag`. Repeat the flag to add more patterns.

```sh
semscope scan --exclude vendor --exclude 'gen/*.go' .
semscope rules inspect --exclude 'gen/*.go' nasa-p10
```

When a ruleset also excludes the pattern, the reason of the ruleset stays.
A bad pattern gives exit status 2.

## Directories that a scan always skips

A scan does not go into a hidden directory. It also skips `vendor`, `node_modules`, `testdata`, `zig-cache`, `zig-out`, `target` and `__pycache__`.
To scan one of these directories, give it as a scan path, for example `semscope scan vendor`. semscope does not skip a directory that the command line names.
